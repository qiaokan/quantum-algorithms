# Authoring contract

The full project requirements are in [SPECIFICATION.md](SPECIFICATION.md). This is an original, locally readable textbook for a programmer with arithmetic but no assumed linear algebra. Do not compress into summaries or fabricate completeness.

## File contract
- Lessons: `src/content/lessons/NN-slug.md`, plain Markdown, math as `$...$` or `$$...$$`, no YAML front matter, no top-level h1 (page supplies title). Stable section headings `## Problem and access model`, `## Classical baseline`, `## ...`. Can adapt to primitives; all A–N requirements need substantive coverage. Write genuine paragraphs with concrete arithmetic. `details`/`summary` HTML allowed; blank lines around Markdown inside. References inline as normal external Markdown links. End with `## References` with title, authors, URL, supported claim. No word-limit constraint; favor complete mechanism over breadth.
- Each research worker owns its `src/content/catalog-GROUP.json` containing array of lesson metadata: `{id, sequence, module, title, kind, summary, why, prerequisites: [stableIds], concepts: [definitionIds], reusedConcepts: [definitionIds], exampleIds: [], sourceIds: [], path: 'main'|'branch', editorial: 'complete'|'partial'|'planned'|'reviewed', advantage, aliases: [], file: 'NN-slug.md', gaps: []}`. `id` is filename without NN- and .md. Default editorial `complete` only when ALL teaching requirements met. `reviewed` requires independent substantive review. `partial` MUST specify exact gaps. Never link blank pages. Root owns overall manifest aggregation.
- Sources: `src/content/sources/GROUP.json`, array `{id, title, authors, url, supports, verified: '2026-11-02'|null, verification: 'full-text'|'abstract'|'official-doc'|'unverified', note?}`. Sources actually opened via web, not invented. Metadata can reference common ROOT source IDs: `ibm`, `zoo`, `end-to-end`, `qsvt`, `qsvt-tutorial`, `hhl`, `aaronson`.
- Exercises: `src/content/exercises/GROUP.json`, array `{lesson: stableId, question, answer}`. At least 2 thoughtful worked answers per lesson. Inline predictions can also appear in prose.
- Definitions: root authors library with IDs: complex-numbers, vectors, matrices, matrix-multiplication, tensor-products, normalization, probability, conditional-probability, basis, inner-products, outer-products, conjugate-transpose, unitarity, eigenvalues, singular-values, reversible-computation, controlled-gates, ancillas, uncomputation, measurement, phase, density-matrices, observables, complexity, oracles, state-preparation, reversible-arithmetic, hadamard-test, swap-test, expectation-estimation, modular-arithmetic, continued-fractions, binary-linear-algebra, hamiltonians, polynomials, groups. Link `[name](/definitions/ID/)`; these open navigable prerequisite stack. Define essential new symbols and concepts in lesson too. Can add your own definitions in files with NEW unique IDs and inform root.
- Links `[earlier lesson](/lessons/STABLE-ID/)`. Use known IDs only; root will validate.
- All mathematical registers big-endian, leftmost bit most significant, column vectors, matrices act right-to-left. QFT positive exponent; inverse negative. Explain deviations explicitly. No software library ordering assumptions.
- Source prose must be original; don't paraphrase whole source passages. Derive own tiny examples; cite provenance of theorem/performance claims. Record uncertainty honestly. Avoid broad complexity claims with missing precision/access assumptions.
- Research notes go `research/GROUP.md`, log sources/verification, any omitted significant family, any unresolved teaching/technical gaps. Actual verification date 2026-11-02.

## Required pedagogical depth
Every chapter needs problem inputs/output/promises/access, fair classical baseline, concrete fixed example with intermediate arithmetic to result, why it works, implementation, scaling/limitations, misconceptions, predictions and answers, backwards/forward connections, inline citations and bibliography. Introduce every symbol. No empty headings or recycled generic caveats. Modern difficult methods may have honestly labeled worked primitive + open derivation gaps; mark partial if so. Distinguish oracle complexity from full runtime; powered U access counts; prepare/readout costs; no unsupported practical advantage.

Root implements simulator (Deutsch/Grover/BV/DJ/Simon/QFT/QPE), site, definitions, tests, orientation, lessons 1–5 and synthesis. Research tasks develop later source-grounded chapters in disjoint file ranges. Do not edit site/package/root files. Communicate early about correctness/dependency issues.
